# RouteCommand demo walkthrough

This is a practical walkthrough of the current local build, not a claim that all planned verification is finished. Phases 14–20 remain open; the driver offline path and turn-by-turn navigation still need their planned review. Do not present those as verified outcomes until that review is done.

## Before the demo

1. Install Node 26/npm 11 and Docker Compose.
2. Follow the [README quick start](../README.md), including migrations and the development seed.
3. Provision local Valhalla data if you plan to show road navigation; see [ROUTING.md](ROUTING.md). Without it, road routing may be unavailable or fall back to degraded guidance.
4. Confirm the web/API/DB/Redis containers are healthy and Mailpit is reachable.
5. Use only the local seeded demo accounts. The shared demo password is documented in README and is never appropriate for a deployed environment.

## Engineering talking points

- **Spatial queries:** PostGIS geography and GiST indexes power proximity and zone checks; see the recorded `EXPLAIN` output and its small-seed caveats in `SPATIAL_QUERIES.md`.
- **Realtime pipeline:** Redis accepts and coalesces location state before asynchronous stream persistence; Socket.IO rooms are authorization-scoped.
- **Security:** role/ownership enforcement, refresh rotation/reuse detection, request validation, rate limits, and privacy-filtered tracking are implemented; Phase 18 review remains open.
- **Map performance:** imperative marker updates and a large-fleet canvas path exist. The remembered FPS review is not a repeatable benchmark; see `PERFORMANCE.md`.
- **State and reliability:** shipment lifecycle/idempotency, assignment locks, alert lifecycle/audit, and offline queue design are documented. Match claims to the relevant phase evidence.
